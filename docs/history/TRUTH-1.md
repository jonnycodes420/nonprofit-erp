## TRUTH-1 · A truth check that can catch a wrong number (2026-10-31)

MAP-1 found that `assertSurfacesAgree` checked screens against SQL written inside the test: it summed soft and matching credit rows as money, its lapsed check compared two screens that call the same code, it had no households check, and it never looked at deposits. TRUTH-1 gives it an answer key. `tests/keys/truthKey.js` computes every number from plain rows by definitions written out in it (no app code); `tests/keys/fromDb.js` reads an org's rows; `tests/keys/build-keys.js` builds the real-shaped files' keys from their cells (they reproduce Jonathan's hand keys to the cent). The check now compares every surface to the key and to each other: the lapsed list by person, households on Donors, Ask, Atlas and Reports, deposits on Finance and the bookkeeper's file, first-time donors by person, each person's lifetime, campaign raised. `tests/truth-key.test.js` holds the key to a hand-worked fixture; `tests/surfaces-agree.test.js` org D holds the four blind spots, and each one, planted back in a scratch copy (a credit summed into lifetime, a lapse rule with no pledge hold, a household counted twice, a deposit read from `deposit_ref`), goes red.

Run against what exists, it found four shared functions summing credit rows, fixed here: the `gifts` figure source (the Board, Home's pace, the annual report), the `givers` source (people who gave, first-time; it also now counts the old system's first gift, as the New tag does), `reportGiftWhere` (every report's rows, so they foot to the fixed figures; it was D-5), `reportAnnual`'s own queries and Fundraising's overview sums (the same reason: once the shared ones were fixed, their rows stopped footing and the Raised tile read "$5,840 ↑ $190"; a judgment call, since each is a duplicate, not the shared version; they were D-1 and D-2) and `donorStatus.statusSql` (a credit row kept someone off Lapsed); `scripts/check-numbers.js` reads hard credit for the same rules. Four duplicates were logged in `docs/defects.md` (D-3, D-4, D-6, D-7: Ask and Atlas, Finance's money in, the bookkeeper reading `deposit_ref`, the onboarding count) and marked in `tests/lib/knownDefects.js`, where each passes only at exactly the value its defect predicts. Two calls: the key follows FIX-60's pledge hold (an overdue pledge holds someone off Lapsed; the brief's words were "on schedule"), and the gift file's distinct names are not compared as people, because the importer rightly folds "Mr & Mrs. X" into X.
