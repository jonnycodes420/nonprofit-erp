# LIST-3 · The last list, search, settings and demo gaps from the walk (2026-11-05)

From Muse's walk (5 Nov) and HOME-6's left-overs. Six items, one theme: what she sees after she acts.

- **Cmd+K showed nothing while typing.** Cmd+K and the top bar were already one component (`GlobalSearch`) and one query (LIST-2's `personMatch`); on a fast local server both worked. The walk was on prod, where each `/search` answer arrives late. An answer was dropped whenever a newer question had been *asked*, so while she kept typing every answer was thrown away and the box showed nothing (the "Go to" list empties once no shortcut matches the word); Enter worked because it waits for its answer. Reproduced only with 0.9 s added to every answer (and the service worker blocked, or Playwright's route never sees the request). Now an answer is dropped only when a newer one is already *on screen*, an older answer shows while it is for the start of what she has typed, and "Searching…" shows (not "No matches") until the first lands.
- **Saved views lost their sort.** The view was saved without it: `POST /donors/list-views` took columns, widths, filters and page size, never `sort`/`dir`. New columns `donor_list_views.sort_by`, `sort_dir` (`server/donors/listViewsSchema.js`; db.js at its size cap, so one call line); picking a view restores them, and a view with none opens in the list's own order.
- **"Asking the people who have given before."** The General appeal's sentence names no merge field, so TRUST-1's `withoutMissingGift` could not see it. `shared/giftSentence.js` now keeps a short list of who-we-are-asking clauses and, for a person with no gift, swaps each for its variant ("we're asking friends of {{org_name}} to join us"). Every renderer (preview, block renderer, legacy send) already calls it.
- **The logo.** Two logos: Settings → Branding saves `orgs.logo_data`; the giving page read only `portal_settings` (its own designer's). Receipts and emails read `portal_settings` first, then Branding's. Now the giving page falls back to Branding's (`GIVE_THEME_COLS`), a Branding save writes the logo to `portal_settings` too (so an older one there stops winning), and Branding's remove takes away only the logo Branding put there. Branding sent `removeLogo` on every save without a logo, colour-only saves included; it now sends the logo only when she changed it.
- **Demo recurring.** The seed already wrote 70 active monthly subscriptions with their gifts and next dates; what it lacked was a canceled one. Rosamund Pellwether, nine monthly gifts, canceled three months ago, with her own ids and a literal name so no other demo person's draw or id moves. Seed only; nothing changes at deploy. Why prod's demo showed no active recurring donor was not reproducible from code (no job cancels them); a reseed puts the seed's state back.
- **/app jumped on a phone.** `/app` had no route: it went through `*` to `/` and then to `/dashboard`, mounting twice, and Home's boot reads (started only for `/dashboard`) began late. With a session, main.jsx now rewrites `/app` to `/dashboard` before anything draws. Phone (tests/lib/phone.js, slow 4G, CPU 4x, cold): CLS 0.408 on main, 0.000 now.

**Test.** `tests/list3-gaps.test.js`, one suite (the brief named six checks). On main 16 of 25 failed (§1 to §6 each red); 25 of 25 pass here. The §1 check reads the dropdown without waiting: a locator's innerText waits for the dropdown to appear, which held the typing back until the answer landed and turned main green.
