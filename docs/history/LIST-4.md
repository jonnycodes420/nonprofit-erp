# LIST-4 · Sort the Donors list by any custom field (2026-11-10)

A beta customer asked on 9 Nov for a score she can filter ("everyone with a 5") and sort either way. Custom fields already showed as Donors list columns, but `donorList.cfField` set `sort: null`, so their headers could not sort.

- **W-1 · A custom field column could not sort.** Reproduced on main with real clicks (Playwright, `NODE_ENV=production`, the built client) on a fixture with one field of every type: each custom header's tooltip read "Drag to move this column.", a click left the order and the address unchanged, no `aria-sort`. Cause: `sort: null`, and `donorList.sortSql` is sync and knows only the built-in `FIELDS`. Fix: `server/donors/cfSort.js`. `groups.buildDonorFilter` sends a `cf:<key>` sort there; the key is looked up among this org's own definitions and only the stored key (plain letters, digits, underscores) reaches the ORDER BY, with no arguments, so every caller of `orderBy` keeps working. Number and money by value, date by day, select by its place in the field's option list (read from the definition row, so no option text is written into SQL), text case-insensitively, checkbox Yes first descending, blanks last both ways. Multi-select is not sortable; its header says why. Another org's key, or a key that was never a field, is a 400 with a sentence; a field archived since a view was saved falls back to the list's own order. Saved views: LIST-3's `cleanSort` took only `[a-z0-9_]`, so it dropped `cf:` silently; it now takes `cf:<key>` and checks the key against the org's fields before saving.
- **W-2 · The filter on a custom Number or Money field was a 500.** Found while building W-1, with the same cause: the db layer turns every `?` into an argument, and `cfCond`'s pattern `'^-?\d+(\.\d+)?$'` holds two. "Wealth Score at least 3" on a custom Number field answered "Internal server error" on main. The pattern is now written with `{0,1}`. What the filter matches is unchanged.
- **The sort dropdown said "Sort: total given"** while the list was sorted by a column the dropdown does not list (any custom field, and City, Added, Wealth Score). It now names that column.
- **Settings → Custom fields:** under Number, "Good for scores: filter by value, sort high to low." (`client/src/components/settings/CfTypeHelp.jsx`, which also took the "type can't change" note out of Settings.jsx, at 1,482 lines.)

**No expression index.** 25,000 people in one org, with a Number and a 1-to-5 Select on six of every seven: GET /donors sorted by the Number answered in about 40 ms, by the Select in about 140 ms (page step 125 ms: the option's place is read per row), Lifetime in about 70 ms. An index on the value would not serve the Select's lookup.

**Test.** `tests/list4-cf-sort.test.js`, 15 checks. On main 14 fail (the one that passes is the sign-in). Planted: the select sorted alphabetically by label makes §2's two order checks red (Five, Four, One, Three, Two).

**Existing rows.** None need a repair: nothing was written wrong. Saved views made before this kept no `cf:` sort (it was dropped at save), so they open in the list's own order until saved again.
